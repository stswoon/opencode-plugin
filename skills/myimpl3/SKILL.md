# myimpl3

Оркестратор планировщика слотов. Production-код сам не пишешь. Статус в плане меняешь **только** после `LEAD_PASS`.

Цикл одной стори (Dev → QA → Lead, гейт доказательного `QA_PASS`, решения `D…`, артефакты, per-story коммит, «Изменение принятых решений», промпты Task) — из skill **`myimpl`**, здесь не дублируется. Разделы `myimpl` «Выбор сторей» и «После волны», лимит волны и правило «волна стартует с чистого дерева» **заменены** этим файлом.

```
4 слота
  └─ заполнить свободные слоты готовыми стори (Dev параллельно)
       └─ батч результатов → QA → Lead → коммит по завершившимся
            └─ сразу снова заполнить слоты, остальных не ждать
                 └─ стоп-условие → дренаж → итог
```

## Слоты

Слот занимает стори «в работе» — от старта Dev до `сделано` или выноса блокера. Максимум **4**. Слот освобождается в момент `LEAD_PASS`/стопа стори.

Оркестратор не получает событий по одной задаче: результаты Task приходят **батчем**. Поэтому точка планирования — каждый батч: обработай завершившихся и тем же сообщением заполни все свободные слоты. Внутри батча решения не ждут остальных.

## Готовность

Взять стори в свободный слот можно, только если всё верно:

1. Статус `не сделано` (нет поля **Статус** — то же).
2. Каждая зависимость `сделано`.
3. Файлы и папки не пересекаются ни с одной стори «в работе» (см. «Параллель» / «Папки» в стори и «Правила параллели» в `docs/plan/README.md`).
4. Эксклюзивные пути заняты максимум одной стори: `src/shared/**`, `src/content/i18n/en.json`, `src/ui/hud.ts`, `src/ui/styles.css`; UI-цепочки — строго последовательно.
5. В её путях нет незакоммиченных правок — чужих или осиротевших от прерванного прогона; такие пути «заняты», пока правки не разрешены (стори доведена или откачена решением пользователя).
6. Пользователь назвал ID — только они; чужие стори не подхватывай.

Кандидаты берутся в порядке ID. Нет готовых, но есть «в работе» — жди батча; заполнять нечем — стоп (см. ниже).

## Статусборд

## Расписание

1. Заполни свободные слоты: по Task `dev` на стори, несколькими Task в одном сообщении.
2. По завершившимся — «Цикл одной стори» `myimpl`: QA по готовому коду, затем Lead по доказательному `QA_PASS`.
3. QA/Lead разных стори — параллельно, но только после сдачи своей стори; QA «на будущее» с первым Dev той же стори — нельзя.
4. `LEAD_PASS` → статус `сделано` и коммит путей стори (`myimpl`), слот свободен → сразу бери следующего кандидата.
5. Провалы — по `myimpl`: `QA_FAIL` → Dev с отчётом и регрессионным тестом; `LEAD_FAIL` → Dev с замечаниями; больше 3 петель — стоп-фактор.
6. Допущения закрывай сам (решение `D…`), нестыковки и расхождения со спекой — вопрос пользователю, как в `myimpl`.

## Остановка

Новых стори не берёшь, если сработало любое:

- **нечем заполнять**: нет готовых и нет «в работе» — нормальный конец прогона;
- **блокер**: стори упёрлась в лимит 3 петель, ждёт ответа пользователя (нестыковка) или её Dev/QA/Lead сдался с отчётом; уже взятые стори доводятся до `LEAD_PASS`/стопа («дренаж»), закрытые коммитятся;
- **батч без прогресса**: ни одна стори не сменила состояние и нечего взять;
- **ID исчерпаны**: все названные стори закрыты или заблокированы.

В стоп не «добивай» проваленную стори и не начинай новых. Статус проваленной не меняешь.

## Ответы пользователя

Пользователь ответил на вопрос или просит поменять `D<N>` — сначала «Изменение принятых решений» `myimpl` (журнал, переделка затронутых стори), только потом снова решай, продолжать ли прогон.

## Итог

Остановился — полная сводка за прогон (структура — «После волны» `myimpl`, но без волн):

- закрытые стори с хешами коммитов (`Sxx: <краткое> (LEAD_PASS)`);
- оставшиеся `не сделано`: готовые к следующему запуску и заблокированные (чем: зависимости, пути, решения);
- причина остановки и блокеры;
- сводка решений `D…` (что решено и почему, альтернативы, стори, файлы) и пути к `.cursor/artifacts/decisions.md` и `.cursor/artifacts/scheduler.md`;
- приглашение «поменяй D<N> на вариант …» и что открывать руками (`npm run dev`).

## Не делать

- Не дублировать `myimpl`: промпты ролей, артефакты, решения, коммиты — только ссылки.
- Не менять `myimpl`/`myimpl2` из этого скила.
- Не ждать закрытия всей партии, чтобы взять следующую стори.
- Не брать стори без зависимостей, с конфликтом путей или с занятыми (незакоммиченными) путями.
- Не запускать QA параллельно первому Dev той же стори; не передавать стори дальше без доказательного `QA_PASS`.
- Не ставить `сделано` после одного Dev без QA и Lead; не коммитить чужие пути.
- Не принимать нестыковку или расхождение со спекой молча.
- Не менять и не удалять прежние решения журнала самому — только по запросу пользователя.
